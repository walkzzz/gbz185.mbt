# 方案对比（gbz185.mbt 0.2.0）

> 对比对象为「在 MoonBit 中实现智能体互联协议栈」的常见替代路线。
> 本文只陈述设计差异与已知边界，不对未实测的性能/生态作断言。

## 1. 对比矩阵

| 维度 | gbz185.mbt | 手写 JSON + 自定义 RPC | 通用 RPC（gRPC/JSON-RPC 框架） | 上游仓颉实现（agentskills-runtime） |
| --- | --- | --- | --- | --- |
| 与 GB/Z 185 分部对应 | 十个包逐一对应 185.1-185.7 + 公共层 | 取决于自建 | 无国标语义 | 有（源实现） |
| 防重放 | 单调序号 + Z3 证明的 `inbox_advance` 裁决 | 需自建 | 传输层可做，但非国标契约 | 有（运行时实现） |
| 身份码 AIC | 逐字符状态机 + 段前缀 | 需自建 | 无 | 有 |
| 能力描述 / 发现匹配 | `covers` / `covers_any` / `missing` + 原子 `matches` | 需自建 | 服务发现另配 | 有 |
| 传输解耦 | sans-I/O 核心 + `transport_async` 扩展 | 通常耦合 | 框架耦合 | 运行时耦合 |
| 编译目标 | native / js / wasm / wasm-gc 同源 | 视实现 | 视框架 | 仓颉生态 |
| 依赖面 | 核心零 mooncakes 依赖 | 低 | 中-高 | 视上游 |
| 错误契约 | `ProtocolError` 全栈分型 | 自建 | 框架自有 | 上游自有 |

## 2. 何时选 gbz185.mbt

- 需要在 MoonBit 项目中**按国标分部**组织协议资产，并希望核心 sans-I/O、可跨目标复用；
- 需要机器可查的防重放/容量/序号不变量（`verify/` 提供 Z3 证明函数并被真实调用）；
- 需要浏览器内演示或 JS 侧复用同一份协议逻辑（`playground` 为同一源码的 JS 构建）。

## 3. 何时不选

- 需要开箱即用的**端点服务**、MQ 分发或国密互联安全层——本项目是协议库，服务端组装与 MQ/国密属上层或后续版本（见 [known-gaps.md](known-gaps.md)）。
- 需要与 gRPC/OpenAPI 生态直接互操作——本项目不提供这类桥接。
- 传输层必须支持双向 mTLS 客户端证书——当前以对端证书 SHA-256 指纹钉扎等效实现（GAP-2）。

## 4. 与上游的关系

`gbz185.mbt` 的协议要素来自上游 agentskills-runtime（仓颉）实现，抽取为独立 MoonBit 库；两者**不是**绑定关系：上游可继续演进运行时，本项目保持「协议语义冻结 + mbti 契约入库」的库形态。重叠部分通过单一模型（`ToolDescriptor`、`AgentIdentity`）钉扎，避免多源漂移。
